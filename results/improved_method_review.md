# 改进检测器与新实验协议：独立审查

2026-10-02。审查目标是帮助实现、验证改进算法，不是以失败评估替代算法贡献。范围为 `code/improved_detector.py`、`research/algorithm_revision_protocol.md`、旧开发数据及新增开发增强产物；定位器由另一审查/实现方负责。本次仅新增本报告，未改源码、原始实验、旧结果或论文，未生成或查看 fresh 测试样本。

**结论：当前扩大后的协议具备最小公平性。绝对能量捷径和直接标签/元数据泄漏未发现；原始候选存在有证据的多声源捷径风险，主线程已在冻结前加入困难负例和频谱消融处理。增强数据及两个模型的契约检查通过，但尚不能据此声称改善了独立测试性能。**

## 具体风险及处理状态

1. **重要：多声源/混合复杂度捷径确有开发期反例。** 对未加入增强负例的旧候选（模型 SHA256 `4c86213c…`），将旧负例 `neg-s-(2i)` 和 `neg-t-(2i+1)` 各自 RMS 归一化再相加，`i=0..5`；场景对为 EE、DD、ED。组成录音均无目标。18 对单体分数约 -1.49 至 -0.35，混合分数约 0.719 至 1.541，相对较高单体平均上升 1.73–1.91。共同增益已被特征消除，纯宽带 DD 也升分，因此不能把初始高开发 AUC 直接归因于目标语义。**这是未增强模型的开发诊断，不是 FPR、fresh 结果或已增强模型的失效判定；分数也不是概率。** 混合改变多个统计量，不能仅凭此唯一确定是哪一项特征致因。

   已采取的响应符合目标：EE/DD/ED/EDE 四组纯干扰增强、组成录音折间分离、fresh 多干扰负例和 39/87 维消融。独立测试前确定这些内容是正常开发，不是测试后补救。多源负例检验虚警鲁棒性；目标仍只在原四场景中出现，因此不能额外声称验证了“目标加两个干扰”的定位能力。协议已明确此边界。

2. **已解决：旧特征缓存可能与新源码错配。** 最初仅按文件存在复用缓存；现以特征函数及 FS/N 摘要、全部原输入 NPZ 名称/字节摘要失配失效，模型也验证特征摘要。独立重算 2000 个原输入的清单摘要一致；抽查 8 个原音频的 87 维特征与缓存完全相同，故未发现当前缓存错配。人为改变内存中的期望摘要后，`Detector.load` 确实拒绝模型。

3. **已解决：39 维消融的音频接口契约。** 当前模型保存 `feature_count`，推理固定截取相应前缀，load 验证 39/87 维；两个已拟合模型均可通过 `analyze(audio)` 调用。39 维版本仍先计算完整 87 维特征，故仅是信息消融，不能声称节省空间特征计算；协议已说明。若后续重排特征，必须重建模型，现有 feature digest 能发现此变化。

4. **需保持的解释边界。** 现有生成器仍把目标定义为四个微扰振荡器、发动机定义为单振荡器，并有固定的频带/调制/声源数量分布；新种子只检验这些分布下的泛化。无需因此停止改进，但开发 AUC、重新混合的旧数据和同分布 fresh 测试不能替代真实目标类别验证。相加独立录音包含各自通道增益、声速等实现差异，宜称“合成混合录音压力测试”，不能默认为一套物理一致场景的传播仿真。

## 已独立核验的实现与数据

- **绝对能量：** 输入先逐通道去均值，再除全帧 RMS；频带能量是总谱归一化后的比例，其余使用谱比值、归一化特征值或相干度。8 个旧正/负音频分别乘 0.001、0.003、73、1000，最大特征差 `1.33e-15`、旧候选最大分数差 `9.10e-13`；加共同 DC 后特征差 `<8e-16`。在这些正常数值范围内，固定单位噪声的绝对能量不是该检测器的输入捷径。这不等价于对削波、独立通道增益或任意频响变化不敏感。
- **泄漏：** `features(audio)` 不接收文件名、label、场景、SNR、真值方向/f0或元数据；标签仅进入监督拟合，元数据用于分组和追溯。原内部训练 1500 条、验证 500 条；标准化只在相应训练折拟合。用全部旧开发数据重拟合最终模型合法，但内部选型分数不再是最终模型独立性能。
- **拟合公式：** 对选用的 `d=39/87` 维，`z=(x-mean_train)/max(std_train,0.05)`；`Kij=exp[-||zi-zj||²/(2*d*width²)]`，`a=(K+ridge*I)^(-1)(2y-1)`，预测 `k(z,Z)a`。代码实现一致，没有概率输出或固定零阈值保证。最终 2800 条训练数据重算中心、尺度和训练矩阵均匹配；87/39 维模型线性方程最大残差分别约 `1.34e-11` / `1.57e-11`。
- **增强 provenance：** 800 条均有音频与记录；四组各训练 150、内部验证 50，合计 600/200。所有组成 ID 属于其原始折，训练与验证组成 ID 交集为空，同一混合内也不重复 ID。8 条跨组/跨折样本用保存权重重建音频逐位一致，重算特征差为 0。重建时应把 JSON 权重恢复为 NumPy float64，保持原混合的数值类型。折内重复使用组成录音属于相关增强样本，内部 AUC 不能附上按 800 个独立物理试验解释的置信区间。
- **输入与模型：** 错误形状、NaN、Inf 音频被拒绝；零音频特征有限（这本身不保证零音频判为负）。两个最终模型的特征数量、前缀推理、增益不变性、加载匹配及不匹配拒绝均经内存检查。未调用会写旧结果的原实验入口。

## 冻结与 fresh 评价的最小公平口径

最新版协议已采纳以下核心设计，可按此推进执行，不需要再增加框架或无限扩展试验：

| 环节 | 冻结口径 |
|---|---|
| 开发 | 原训练 1500 + 增强 600；原内部验证 500 + 增强 200；各候选仅在这些旧数据上选参数，最终两模型均拟合全部 2800 条。87 维不预设优于 39 维。 |
| 阈值 | 800 个新负例，八组各 100；每个检测器分别在**同一批**音频上取自身第 761 顺序统计量，严格大于才检出。原检测器也按此重校准，不能拿旧数据阈值作不对称对比。内部开发 quantile 阈值不转移给全量重拟合模型。 |
| 测试 | 1000 个新正例（4×5×50）及 2000 个新负例（8×250）。冻结后只报告，不再按测试 AUC/召回切换候选或阈值。 |
| 混合权重 | 总 FPR 为八组等权；同时报原四组、多干扰四组和逐组 FPR。此总 FPR 对应声明的合成混合比例，不是任意背景的统一 5% 保证。正负 1:2 时使用声明的 balanced accuracy，不能与普通 accuracy 混名。 |
| 独立性 | fresh seed 命名空间与所有开发/self-test 分开；组成录音不跨校准/测试复用，也不在不同测试 trial 间复用，保存 seed、组成 ID、hash。只有满足此点，才能按整个混合 trial 作为独立 bootstrap 单位。 |
| 改进归因 | 原始定位在全部同一组正例上配对；联合指标比较“旧检测+PHAT / 新检测+PHAT / 新检测+新定位”，均用全部正例为分母。条件误差必须带检出数，不能因 gate 改变选样就宣布定位算法改善。 |

另有两项执行时应保持的小检查：

- 区间对新旧差值逐 trial 配对，按已声明场景/SNR或八组负例分层；不把四算法行、组成音频或增强副本视为独立样本。报告固定模型和固定校准阈值下的不确定性，不能称包含重新训练/重新校准的全部不确定性。
- 性能计时包含单帧特征提取、对全部 2800 个训练支持样本的核预测以及所选定位路径；批量 `predict` 均摊时间不能替代逐帧在线成本。声明重复或共享的前端和排除项；39 维消融目前不支持提取加速主张。保留已有整体增益不变性检查即可，不要求为此新增外场或未来模型。

### 评价器

- `negative` 的生成器和 RNG 均替换为纯记录桩：校准 800 条调用 1300 个独立组成 seed，负测试 2000 条调用 3250 个组成 seed；合计 4550 个组成元组无重复，1400 个混合权重元组也无重复。1000 个正例和 24 条序列的符号化 seed 集合与之不交。此处只是检查元组，不是生成样本。

### 候选定位器

- `candidates(audio)` 从 PHAT、完整帧谱权重及三个音频估计的 f0 假设图生成候选；候选及 149 维特征完成后，开发函数才读取真值并生成监督目标 `exp[-(error/10)^2]`，负例目标为零。推理不接受标签、方向、SNR或场景。`candidate_oracle_*` 只属候选集上限诊断，没有进入实际胜出候选选择。
- 旧缓存共 8750×149，所有特征和标签有限；逐项核对全部监督目标符合上式。重建五折后，每折 400 个完整 trial（正例 200），同一 trial 的所有候选始终在同一折，折内标准化、anchor 选择仅使用训练子集。最终全数据模型不是 OOF 模型，开发 OOF 结果不能当 fresh 测试。
- 6 个旧正/负音频的候选索引、149 维特征与缓存完全一致；乘 3 后候选不变，最大特征差 `5.67e-14`。完整模型的标准化、按训练标签选择的 anchors 与重新推导一致，加权岭方程相对残差约 `1.18e-14`。
- 确定性单频阵列响应检查确认：向源方向的负号时延与 `exp(+j*2*pi*f*tau)` 对齐，目标方向的延时求和增益为 1；`beam_c - rho*beam_other` 对另一候选源置零。分母采用 `max(1-|rho|²,0.1)`，其 floor 生效时会衰减目标增益；方法公式必须保留这个稳定化项，不能声称所有频率严格无失真。这是已知设计取舍，不是反号 bug。
